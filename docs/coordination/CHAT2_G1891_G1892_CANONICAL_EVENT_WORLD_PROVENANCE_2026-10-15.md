## Boundaries
- A `World` object reference is process-local and ephemeral. This cannot enforce cross-JVM account ownership/epoch or prevent original attacker attribution mistakes.
- The code still does not make `dispatcher.deliver(correctWorld,oldFinalizedEvent)` a safe replay operation. Re-delivering into the *right* World is NOT an authorized outbox/retry path. `RETURNED`≠ applied objective; `THREW` may already have side effects.
- Durable event identity, atomic per-consumer objective postimage+ACK, source-verified kill attribution, account writer fencing, grants and ACTIVE recovery remain open: [#2587](https://github.com/Trexzo/SpawnPK-RE/issues/2587), [#2558](https://github.com/Trexzo/SpawnPK-RE/issues/2558), #2540/#2559.
