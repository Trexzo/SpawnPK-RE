# G21.108 — pinned PREPARED/COMMIT byte witnesses (NO AUTHORITY)

Parent G21.107 [PR #2394](https://github.com/Trexzo/SpawnPK-RE/pull/2394), exact `43b542d03a8856d7a703d7e36da66d69c5ed8935`, Actions #38140254437 SUCCESS, 407/407 Java 11. Issue #2395.

G21.107 proved an independently pinned canonical account SHA-256 at two bounded G21.106 observation passes. The PREPARED journal and COMMIT sidecar had only NOFOLLOW physical identity/size/mtime evidence. A same-inode same-size mutation with restored mtime could therefore survive that check.

G21.108 adds opt-in `comparePinnedRecoveryLeaves`: require the separately pinned portable v1 archive SHA-256, canonical account SHA-256, and PREPARED plus COMMIT proofs. Each sidecar proof is either an externally pinned lower-case SHA-256 of its present file or the exact explicit `ABSENT` expectation. Within *each* of two G21.106 lifecycle-locked observations, take paired before/after bounded NOFOLLOW physical-key/size/mtime/byte-count and SHA-256 sidecar reads inside the account-publication lock around v1 recapture. Change, unexpected presence/absence, malformed pin, nonregular/symlink leaf, zero-length or greater than 1 MiB, and unequal content are fail-closed. Preserve G21.106 and G21.107 APIs; only opt-in reports `pinnedRecoverySidecarBytesMatched=true`. All positive authorities remain explicitly false.

A standalone focused integration test creates a real canonical account and valid opt-in writer evidence but uses **synthetic sidecar byte fixtures**. It tests byte evidence, not validity of PREPARED/COMMIT protocol records or any session ability. Tested cases: both sidecars absent, both present, wrong/malformed digest, unexpected/missing leaf, in-place same-inode/same-size restored-mtime tampering on each, interpass COMMIT change, oversized and nonregular rejection, original fixture restoration and no leaked cooperating publication leases. Java 11 manifest 407→408.
