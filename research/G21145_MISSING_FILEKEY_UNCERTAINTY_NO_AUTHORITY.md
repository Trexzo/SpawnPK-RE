# G21.145 — missing NOFOLLOW fileKey is UNCERTAIN, not a historical identity match (NO AUTHORITY)

Certified parent G21.144 [Draft PR #2468](https://github.com/Trexzo/SpawnPK-RE/pull/2468), exact `782e66cae084b8fc84b69f0d2ec471eaa8fb6b73`, [Actions #38291898866](https://github.com/Trexzo/SpawnPK-RE/actions/runs/38291898866) SUCCESS Java11 focused 444/444. Issue #2469.

**Proven issue:** Java `BasicFileAttributes.fileKey()` MAY be null. G21.144 compares historical/current source metadata via `PhysicalIdentity.sameMetadata`, which used `Objects.equals(fileKey, other.fileKey)`. If BOTH keys were null, that expression evaluates to true and the historical-to-current comparison could return `MATCHED_OBSERVED_METADATA_NO_AUTHORITY` despite lacking any historical identity value from either observed file. That is a confidence-classification bug, NOT proof of malicious activity. Filename, SHA and mtime equivalence alone do not establish unchanged inode identity.

**G21.145 read-only correction:** Extend the *existing*, strictly in-memory `MailboxSevenPlaneHistoricalIdentityDeltaV1` to retain `changedSources` and add immutable, sorted `uncertainSources`, collecting a precise label for any account, PREPARED journal, COMMIT, or original v1/v2/v3 evidence leaf whose historical/current fileKey is absent. Three disjoint classifications by precedence: CHANGED (actual observed filename/content/physical metadata drift), UNCERTAIN_MISSING_FILE_KEY (no concrete observed drift, but missing source identity), MATCHED (no drift and all compared NOFOLLOW fileKeys present). A missing whole source identity still counts as concrete CHANGED, not just uncertainty. When a source has both known drift AND no fileKey, CHANGED takes precedence and the unknown source is also recorded as uncertain. Portable SHA and payload comparison remain unchanged. The helper still reads no files, takes no locks and mutates nothing. All grant, replay, cleanup, rollover, pruning, unlink, session, release, ACK, authenticated provenance, RAW/default/history/future exclusion, power-loss and atomic-epoch fields remain FALSE.
