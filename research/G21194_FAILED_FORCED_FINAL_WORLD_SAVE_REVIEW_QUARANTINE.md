The test enables all cooperating experimental opt-ins (JVM account session lease, cross-JVM OS lock, existing-review marker veto, one-shot forced ACTIVE marker before World registration, and G21.192 forced World postimage). An initially absent disposable account logs in through real synthetic TCP. The already stored BOOTSTRAP file and the ACTIVE marker must stay byte-identical; the uncommitted mutation must not appear in forensic disk load. A **new World in the same JVM**, using a new repository, then attempts actual socket login and is denied without registering a player or acquiring **an additional** account lease. The original failed-final-save JVM lease deliberately remains retained (G21.181/G21.182 fail-closed contract), so this test by itself does **not** isolate the persisted marker as the sole veto across a fresh process; that requires separate process-level evidence.

This is a narrow failure-before-account-replacement cutpoint: the test deliberately faults after temporary World snapshot preparation/force and **before** replacement, not after ATOMIC_MOVE or directory force. No promise of post-rename crash recovery, machine power loss, inter-JVM forced-save failure, raw/uncooperative writer exclusion, or positive repeated logins. The marker has **no retirement API**; the result is permanent one-shot quarantine even after a forced bootstrap save. The failure is **injected** deterministically, not a real filesystem disk error.
