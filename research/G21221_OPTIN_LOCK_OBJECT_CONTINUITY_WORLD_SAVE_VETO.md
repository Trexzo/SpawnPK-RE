## Security limitations (critical)

This **does NOT repair G21.219's two-JVM lock path substitution attack** or implement a globally authoritative epoch. A hostile process can rename/unlink *after* an identity check and before a file replace, create a new inode matching the old name in another JVM, or modify the account file without consulting any lock. Java standard `FileChannel` in this code does not independently prove the observed path fileKey belongs to the file descriptor acquired earlier when an adversary can concurrently swap the pathname. No filesystem check fully closes the time-of-check/time-of-use window here. A passing G21.221 means **best-effort fail-closed detection of already observed drift**, not authoritative cross-process fencing. Do not claim full safety, positive reconnect, crashed-owner ACK, recovery, ACTIVE marker retirement, original SpawnPK server parity or gameplay reward authority. Next real milestone must design a persistent authenticated owner-generation and account-postimage commit protocol plus trusted lock directory/object controls and full writer coverage. Keep #2540/#2559 and #2587 OPEN.
