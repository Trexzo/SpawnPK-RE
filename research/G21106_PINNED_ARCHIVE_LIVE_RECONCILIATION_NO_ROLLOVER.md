# G21.106 — externally pinned archive-to-live evidence, two-pass negative reconciliation

Certified parent: G21.105 `f9072405d930208d1fbcbc56b807e2ef67390b32`, [Actions #38137379154](https://github.com/Trexzo/SpawnPK-RE/actions/runs/38137379154) SUCCESS, 405/405 Java 11; issue #2391.

G21.105 produced portable record bytes and a digest, but that snapshot alone does **not** show whether the same record leaves, authoritative account, PREPARED journal or COMMIT sidecar are still present on a particular source machine. G21.106 introduces `MailboxWriterArchiveLiveReconciliationV1.compare`: independently verify the portable manifest against an externally pinned SHA-256, pin its exact account path once, and take **two separately locked** bounded read-only observations against current source files. Each pass uses the existing G21.100 cooperating lifecycle lock then G21.99 publication audit before and after the actual G21.105 archive byte capture. The two passes must return the same canonical account/journal/COMMIT NOFOLLOW file identities/size/mtime and the same bounded temp candidates, and reconstruct the exact original portable content and trusted hash. Any differing physical witness, record content, version, account, count or SHA-256 fails closed. A test-only callback can run between passes with no locks held.

**Real OS JVM acceptance:** Full 32-record v1 ledger remains unchanged after a separate new JVM loads its externally pinned archive and successfully compares it against live source. A separate legacy-style JVM, never taking the G21.100 lifecycle lock, atomically replaces a canonical account with **identical bytes** and a different physical inode *between* passes; G21.106 must catch this physical drift despite identical v1 archived records. A second old-style writer publishes **after** both passes succeeded, explicitly demonstrating no future writer fence or cleanup token. Tampering with a source record's bytes with size/mtime restored fails the exact v1 payload validator; removing one record fails digest/record comparison; injecting v2 mixed-version evidence fails; a valid but different account's archive is rejected. Tests compare original source account bytes and untouched archived record byte strings, and check zero leaked JVM leases. Manifest Java 11 405→406, standalone `g21106MailboxPinnedArchiveLiveReconciliationRegression`.

**Safety limits:** This checks only a bounded moment; it neither prevents a legacy/raw write after the check nor proves content of account files or durability on power loss. The SHA-256 must be independently pinned from a trusted channel; no signing, remote archive storage, retention rollover, pruning, cleanup, delete, COMMIT promotion, World session restoration, item claim, replay, release or ACK.
