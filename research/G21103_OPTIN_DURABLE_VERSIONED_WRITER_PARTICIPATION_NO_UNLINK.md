# G21.103 — opt-in versioned durable writer participation (no cleanup authority)

Parent G21.102 certified `bb770db32477d8263026f39729f688d39925bfc6`, [Actions #38126089898](https://github.com/Trexzo/SpawnPK-RE/actions/runs/38126089898) SUCCESS, 402/402 Java 11 focused. Issue #2385.

**Purpose:** G21.100 lifecycle locks and G21.102 two-pass physical witnesses are necessarily transient. After a JVM crash, the OS lock disappears; the mere fact that a current version can obtain that lock does NOT prove earlier writer generations have ended or that an orphan can be unlinked. G21.103 introduces a new **explicitly opt-in v1 evidence protocol**. It does **not** add more filesystem work to the three already performance-sensitive strict account, PREPARED journal, and COMMIT hot paths until rollout, version negotiation, writer population and recovery policy can be separately reviewed.

**Protocol:** `MailboxWriterAttemptEvidenceV1.runRecorded(resolver,account,action)` pins the canonical account path exactly once, obtains the existing G21.100 bounded cooperating per-account lifecycle lock, creates a UUID-qualified, account-bound, version-tagged immutable `BEGIN` record BEFORE running the action, then creates a matching immutable `COMPLETE` record only after normal completion. Each record is serialized with strict ASCII fields for protocol version, exact account, exact UUID and stage; bytes are forced, the record is published with a create-only hard link, and the directory is forced. Neither immutable record is deleted or overwritten, even after crash or exception. Unknown writer generations are never considered covered.

**Read-only recovery:** `inspect` acquires the same bounded lifecycle lock, scans up to 32 account-qualified versioned records, validates physical file identity, NOFOLLOW, content size and full exact account/UUID/version/stage payload, and distinguishes `NO_VERSIONED_EVIDENCE_LEGACY_OR_UNKNOWN`, `INCOMPLETE_ATTEMPT_NO_CLEANUP` and `ALL_OBSERVED_ATTEMPTS_PAIRED_NO_CLEANUP`. An unmatched COMPLETE, malformed record, unknown version, unsafe file or over-capacity fails closed. Even a fully matched pair has `completeWriterPopulationKnown=false`, `everyHistoricalGenerationParticipates=false`, `crashEpochSealed=false`, `unlinkAuthorized=false`, `cleanupAuthorized=false`, and all grant, replay, session, release and ACK authority false.

**True process tests:** independent JVM performs `Runtime.halt(125)` after a durable BEGIN before COMPLETE and an independent new JVM reads the unmatched BEGIN. Separate independent JVM writes and forces a BEGIN/COMPLETE pair and another fresh JVM verifies pairing. Fifth fresh JVM checks absence of v1 evidence for a valid legacy account. Parent verifies account bytes and immutable evidence unchanged and adversarial corrupt payload, version 2, completion-without-begin and bounded record overflow all fail closed. Does not remove markers or orphans except test fixture teardown.

**Critical limitations:** Opt-in test/protocol scaffold, NOT default production writer enrollment or deployment-wide participation proof, transactional account rollback, session recovery, garbage collection, safe temp unlink, COMMIT promotion/deletion or exact-once rewards. Record creation is durable to successful force calls on the test filesystem, NOT proof of hardware-power-loss ordering across devices. A raw/legacy writer can ignore both markers and locks. No regular World session admission, live claim, grant, replay, release, ACK; frozen R25 #1847 and G21.87/88 unchanged.
