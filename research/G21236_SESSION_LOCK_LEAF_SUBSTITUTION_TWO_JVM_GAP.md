# G21.236 — replacement OS lock-file object allows a second process owner

Parent [G21.235/G18.9.0 cumulative Draft #2720](https://github.com/Trexzo/SpawnPK-RE/pull/2720) exact `0ff03fe29b4bd78eb090811116df11f3dbda692c`, 569 focused, own CI required. G21.185's process exclusion holds an advisory FileLock on a stable sibling `.session.lck` file and intentionally does NOT unlink that file during cooperative release. However a test-only actor capable of modifying that directory can unlink and recreate the lock filename while the first JVM continues holding the old inode.

G21.236 starts a real registered WorldPlayer/session token in JVM A with ALL five optional account/session/raw/inode/hardlink flags ON and G21.185 OS lock open. It reads the lock leaf's NOFOLLOW fileKey, test-only unlinks and recreates the leaf and asserts a NEW fileKey, then starts another REAL Java process for the same named account with same flags. JVM B acquires a distinct kernel FileLock on the new leaf and registers a World owner while JVM A retains its original World token. A rendezvous marker proves simultaneous ownership, and both processes clean up. No account data are written; this is an OS lock object identity GAP, not normal TCP exploit evidence or automatic crash recovery.

The test requires a POSIX-capable isolated temp filesystem permitting unlink of a held lock leaf. Under Windows the unlink can be refused by OS semantics; that is NOT an assertion about platform vulnerability. A PASS means **path text alone cannot enforce process ownership in face of lock-file replacement**, not that an ordinary remote client can perform filesystem mutation. One new self-contained Java test, Gradle 569→570, research note, ZERO production changes.

Possible separate response: opt-in testable lock-handle/path object identity checks for cooperating World capture/load/RAW writers, refusing after observed replacement; still cannot restore old OS lock or make a late check atomic with adversarial unlink. A durable epoch/authenticated owner protocol is required before safe relog or ACTIVE marker retirement. Draft/unmerged, hosted exact-head Java11 major55, 570/570 focused and full Gradle required.
