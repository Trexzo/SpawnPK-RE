# G21.144 — bounded cross-report physical identity delta (NO AUTHORITY)

**Certified parent:** G21.143 [Draft PR #2466](https://github.com/Trexzo/SpawnPK-RE/pull/2466), head `50b34db91f0d3391853007a692a000fc4440539f`, [Actions #38290432620](https://github.com/Trexzo/SpawnPK-RE/actions/runs/38290432620) SUCCESS Java11 focused 443/443. Issue #2467.

**Actual gap:** G21.143 empirically proves a fresh G21.129/G21.134 source observation can accept a stable same-byte, same-mtime **new inode**, because source SHA pins are of content and no authenticated prior fileKey is available. This is a correct but limited read-only result. Where a caller explicitly retains an **earlier physical Report**, we can compare its observed fileKey/created/size/mtime/SHA against a new physical Report to detect identity differences across snapshots. The reports themselves are not authenticated and do not establish write history, crash-atomicity, signed provenance or cleanup/grant authority.

**New bounded production read-only helper:** `MailboxSevenPlaneHistoricalIdentityDeltaV1` accepts exactly two already-captured `MailboxSevenPlaneContinuousPhysicalWitnessV1.Report` values and performs **no disk access, lock acquisition, mutation or replay**. It compares historical `after` with BOTH current `before` and current `after` for account, PREPARED journal, COMMIT, and each bounded v1/v2/v3 evidence-leaf name and physical identity, including fileKey/created/size/mtime/content SHA. It also compares pinned portable v1/v2/v3 SHA and string contents. It returns an immutable sorted set of exact changed-source labels, with status either `MATCHED_OBSERVED_METADATA_NO_AUTHORITY` or `CHANGED_OBSERVED_METADATA_NO_AUTHORITY`. Every external historical authentication, raw/default/future writer fence, independent pin, atomic recovery, power loss, pruning/rollover/cleanup/unlink and live grant/replay/session/release/ACK field is hardcoded false.
