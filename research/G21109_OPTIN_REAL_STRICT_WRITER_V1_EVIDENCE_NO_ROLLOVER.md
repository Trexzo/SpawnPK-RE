# G21.109 — real strict writer, explicit opt-in v1 attempt evidence

Certified parent G21.108 [PR #2396](https://github.com/Trexzo/SpawnPK-RE/pull/2396) exact `85ce81f6ec35f7dc1d236bcb86fad5a025ba6e59`, [Actions #38141478523](https://github.com/Trexzo/SpawnPK-RE/actions/runs/38141478523) SUCCESS, 408/408 focused Java 11. Issue #2397.

G21.103–104 created forced, immutable account-qualified v1 BEGIN/COMPLETE attempts, but that generic wrapper had not enrolled a concrete strict snapshot file publisher. G21.109 adds `StrictDurablePlayerSnapshotWriter.saveStrictWithWriterEvidence`, a **non-World per-call opt-in** to a real G21.23 strict save. G21.100 lifetime is acquired ONCE and covers G21.104 preflight/capacity veto, durable BEGIN, existing strict temp serialization and atomic replace+directory force, and then durable COMPLETE if—and ONLY if—strict save returns a Receipt. The new `runRecordedInsideWriter` reuses the exact G21.103/104 preflight and forced records **without** nested lifetime locking. Existing generic `runRecorded` delegates to this helper under its prior lock. The account resolver path is selected once before lifetime acquisition, unchanged by optional wrapping.

The preflight rejects a prior incomplete BEGIN, unknown/malformed version, over-capacity ledger, or fewer than two record slots before touching the strict file. An injected pre-replacement failure produces BEGIN only and leaves the existing account untouched. A real independent JVM `Runtime.halt(129)` AFTER actual strict directory force leaves a durable BEGIN with possibly replaced canonical bytes and no COMPLETE; an independent restart process refuses a subsequent opt-in strict save, leaving disk bytes unchanged. A full 32-leaf ledger denies before an actual save. The ordinary strict method is explicitly tested to remain unrecorded; neither historical nor uncooperative writer coverage is claimed.
