# G21.116 — opt-in JVM-local cooperating writer attempt watch; no generation fence

Certified parent G21.115 [PR #2410](https://github.com/Trexzo/SpawnPK-RE/pull/2410), exact `ee5654f01bc3f866d7048c99e2139d55e09926a7`, [Actions #38149637474](https://github.com/Trexzo/SpawnPK-RE/actions/runs/38149637474) SUCCESS Java11 415/415. Issue #2411.

G21.115 already compares five independently pinned content planes twice and fails closed when canonical account/PREPARED/COMMIT/v1/v2 typed bytes or physical witnesses change, but unchanged/coincidental content cannot reveal every attempted writer. G21.116 adds only a **negative diagnostic**: `MailboxPublicationWriterLifecycle.withWriter` notifies an optionally armed, JVM-local watcher AFTER owning the existing G21.100 lifetime lock and BEFORE executing the writer callback. The notification holds only a short synchronized in-memory map guard, with NO disk I/O, callback execution, extra account file lock or new file. No watch = ordinary writer behavior remains unchanged.

`MailboxLocalWriterAttemptWatchV1.comparePinnedTypedRecoveryLeavesWatchLocalAttempts` resolves the account exactly once, arms a bounded one-account/one-scope watch, runs the entire unchanged G21.115 opt-in five-plane comparison and refuses if any G21.100-cooperating writer attempted to execute in **THIS JVM** before the watch closes. The scope disarms in AutoCloseable/finally even on thrown errors; concurrent overlapping watches for the same account are rejected. A zero-content or failing writer callback still counts as a conservative attempt; different accounts are independent. No monotonic account history, memory leak, timestamps, persistent evidence, source authentication or read-side reward authority.

Focused Java 11 415→416 integration test `g21116MailboxLocalWriterActivityWatchRegression`: real four-kind typed World account, clean pinned witness, existing five-plane API accepts a harmless same-account lock acquisition while new watch denies it, real ordinary/non-World strict save observed without v1/v2 additions, unrelated-account strict save ignored, rejected writer attempt counted, watch callbacks unregistered on failure and duplicate watch admission denied, no inventory grant/lock leaks. A direct raw filesystem in-place write with same bytes and a second JVM holding G21.100 **DO NOT** notify the first JVM’s in-memory registry. Those two negative demonstrations explicitly prohibit any claim of universal writer-generation fencing or retroactive detection.

This is **NOT** a complete writer census, cross-JVM file or process lock, historical provenance proof, power-loss durable state, permanent epoch, cleanup/unlink/pruning/rollover grant, World session/replay/reward/release or client ACK.
